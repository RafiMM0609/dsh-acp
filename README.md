# Agent providers for DeepSeek Harness

Open **Settings > ACP providers** in DSH Web or Desktop to add, edit, enable, disable, remove or test agent connections. This plugin supports three wire protocols: standard ACP (including Antigravity and OpenCode), Pi stdio RPC, and Codex `app-server`. Presets and launch arguments select the protocol; configuration files can explicitly set `protocol` to `acp`, `pi` or `codex` for custom commands.

The CLI must be installed and signed in on the machine running DSH. Executable detection runs there. Home paths such as `~/.codex` and supported agent configuration-directory environment variables expand on that host. On Windows, npm launchers resolve to their Node entry point when possible. Linux uses the installed executable on PATH.

Choose **Load models from agent** to fetch the runtime's model catalog using its existing sign-in. Discovery does not send a chat prompt or save automatically. Saving selected models updates DSH routes without restarting. A successful probe/catalog response does not establish model account access. Pi model IDs shared by multiple providers are qualified as `provider/model` to preserve provider identity; model-selection errors stop the request instead of silently using another model.

Provider configuration lives in `~/.dsh/acp-engines.json`. Environment values are stored as plain text and masked in the editor. Management routes under `/api/acp/*` use DSH browser authentication; mutations require the same origin. Restart DSH and refresh its client after updating plugin code.

Processes launch in the chat workspace taken from DSH's live session metadata. ACP and Codex processes are scoped to provider and workspace, with separate native sessions/threads per chat. Pi RPC has one mutable agent session per process, so it gets a dedicated process for every provider/workspace/chat combination. Switching chats never switches the same Pi process's context. Concurrent turns in the same chat are rejected. Requests without session IDs use short-lived processes and cannot inherit an unrelated conversation.

Text, reasoning, usage and native tool lifecycle events are translated into DSH stream blocks. ACP `tool_call`/`tool_call_update`, Pi `tool_execution_*`, and Codex `item/started`/`item/completed` report progress and failures. Reasoning and text can alternate without reusing a closed block. Pi completion supports `agent_settled` and the older `agent_end` followed by an idle-state check.

Stop settles the local stream and removes its prompt handlers even if the agent ignores cancellation. Pi's dedicated process is stopped. ACP receives `session/cancel`; Codex receives `turn/interrupt` with a known turn ID. A cancelled shared process is recycled before reuse once other active chats finish, or retired after a short cancellation grace period when no chat is active. Other active chats continue while abandoned remote sessions are released. Process exit, spawn errors and disposal reject all pending requests and completion waiters. Provider edit, disable, delete and restart stop all of its workspace/chat processes.

The process pool holds at most 16 entries. Idle entries expire after 10 minutes and are swept at least once a minute; a full pool evicts an idle entry and rejects new work if every entry is busy. Native sessions are recycled after 128 creations per process, when no other chat is active. A recreated runtime gets DSH history as text; native session IDs are not resumed.

Per-engine limits can be set in configuration or through the management API: `requestTimeoutMs` (30 seconds for control requests), `inactivityTimeoutMs` (3 minutes without agent events), `maxOutputBytes` (8 MiB per turn), `maxFrameBytes` (4 MiB per JSONL line), and `maxSessions` (128). Limits must be positive integers. The stream queue and per-turn tool bookkeeping are also bounded. Running tools that emit progress refresh the inactivity deadline.

The current bridge supports text input and the runtime's native tools. It does not forward DSH tool schemas through MCP and does not support image/audio attachments. Unsupported approval or interactive-input requests are cancelled/rejected with an explicit error instead of silently waiting; they are never automatically approved. The legacy `autoCompactTokens` and `compactIdleThreads` settings are stored only and do not trigger compaction.

Run `node --test test/*.test.mjs` with dependencies from the adjacent `deepseek-harness` checkout installed. Tests cover the three wire protocols, model routing, Pi chat isolation, parallel workspaces, tool progress, streaming block validity, Stop, crash recovery, timeouts, frame/output limits and idle pool eviction.
